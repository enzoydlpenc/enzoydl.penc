📦다른 호스팅 방법 (필요시 참고)

다른 플랫폼으로 이전하거나 백업 사본을 호스팅하고 싶을 때 참고하세요.

1

Netlify Drop 가장 간단

30초 안에 무료 URL 생성, 계정 없이도 임시 사용 가능

  1. app.netlify.com/drop 접속
  2. 이 HTML 파일을 브라우저 화면에 드래그&드롭
  3. 자동 생성된 URL이 표시됨 (예: https://xyz.netlify.app)
  4. URL을 팀원에게 공유 — 모바일에서도 즉시 접속 가능

💡 무료 계정 가입 시 영구 URL 보장 (미가입 시 1시간 후 만료)

2

GitHub Pages 영구 무료

GitHub 계정 보유 시 영구 URL 생성, 업데이트 시 자동 반영

  1. GitHub 로그인 → 새 저장소 생성 (Public, README 포함)
  2. "Add file" → "Upload files"로 이 HTML 파일을 index.html로 이름 변경 후 업로드
  3. 저장소 → Settings → Pages 메뉴
  4. "Branch"를 main으로 선택 후 저장
  5. 약 1분 후 https://[사용자명].github.io/[저장소명] URL 활성화
3

Cloudflare Pages 영구 무료

빠른 CDN, 한국 접속 속도 우수

  1. pages.cloudflare.com에서 계정 생성
  2. "Create a project" → "Direct Upload" 선택
  3. HTML 파일을 업로드하고 프로젝트 이름 입력
  4. 자동으로 https://[프로젝트명].pages.dev URL 생성
⚠️
중요: URL 공유 ≠ 데이터 공유

위 방법으로 공개된 URL은 어플리케이션 자체를 모두에게 보여줍니다. 하지만 각 팀원이 업로드한 PDF/시설 정보는 본인 브라우저에만 저장됩니다.

팀 데이터 동기화는 다음 절차로 수행하세요:

  1. 관리자가 매일 업로드 → 설정 → 📤 내보내기
  2. JSON 파일을 카카오톡/이메일/공유 폴더로 팀원에게 전달
  3. 팀원은 설정 → 📥 가져오기로 최신 데이터 로드

실시간 자동 데이터 동기화가 필요하다면 Firebase / Supabase 등의 백엔드 연동이 필요하며, 별도 추가 개발이 요구됩니다.

Firebase 설정

CLOUD SYNC SETUP
상태 확인 중...
📋 설정 단계 (처음 한 번만) — Spark(무료) 플랜으로 운영
  1. console.firebase.google.com 접속 → 새 프로젝트 생성
  2. Build → Authentication 메뉴 → "이메일/비밀번호" 로그인 방법 활성화
  3. Authentication → Users 탭 → "사용자 추가"로 관리자 계정 생성
    예: admin@srf.com / 임의의 강력한 비밀번호
  4. Authentication → Sign-in method → "익명" 로그인도 활성화
  5. Build → Firestore Database → "데이터베이스 만들기" → 위치는 asia-northeast3 (서울) 권장 → "프로덕션 모드" 선택
  6. Firestore의 "규칙" 탭에서 아래 규칙 붙여넣기 → "게시": 
    rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read: if true;
      allow write: if request.auth != null
        && request.auth.token.firebase.sign_in_provider == 'password';
    }
  }
}
  7. 프로젝트 설정 (⚙) → 일반 → "내 앱"에서 "웹 앱 추가" ( 아이콘) → 앱 등록
  8. 표시된 firebaseConfig 객체의 내용을 복사 → 아래에 붙여넣기

✅ 완전 무료 (Spark 플랜) · PDF는 Firestore에 청크 분할 저장되므로 Storage 활성화/Blaze 플랜 등록이 필요하지 않습니다. 신용카드 등록도 불필요합니다.
📊 한도: Firestore 1GB 저장, 일일 50K 읽기 / 20K 쓰기 (광주SRF 예상 사용량 충분 커버)

※ apiKey 등의 값은 Firebase 보안 규칙으로 보호되므로 공개되어도 안전합니다.
